# 재고의 내일 — 웹 대시보드

기존 시각화 사이트와 동일한 HTML/CSS/JavaScript 화면입니다. React·Streamlit 없이 실행되는 정적 웹이며, `dist/`가 완성된 배포 파일입니다.

## 바로 실행

저장소 최상위에서 실행하세요.

```sh
python3 -m http.server 8000 --directory web-dashboard/dist
```

브라우저에서 http://localhost:8000 을 여세요. JSON을 HTTP로 읽으므로 HTML 파일을 더블클릭하는 대신 위 서버를 사용합니다. 시연용 가공 데이터가 포함돼 있어 원본 CSV나 Python 모델 설치 없이 화면이 실행됩니다.

## 다른 호스팅에 배포

- 배포 루트 / 게시 디렉터리: `web-dashboard/dist`
- 빌드 명령: 없음
- 시작 문서: `index.html`
- 해당 폴더 **전체**를 정적 호스팅에 게시합니다. JSON·JS·CSS 파일도 필요합니다.
- GitHub에 코드를 올리는 것만으로 사이트가 자동 배포되지는 않습니다. GitHub Pages 등을 사용할 때 소스 디렉터리를 따로 지정하거나 Actions로 위 디렉터리를 게시하세요.
- Sites 전용 프로젝트 ID와 인증 설정은 포함하지 않았습니다.

## 화면 흐름

1. **발주 신청**: 엔진 추천(기본), 안정형(0.7배), 공격형(1.3배) 선택 → 특이사항/프로모션 미리보기·적용 → 품목별 발주 수량 수정 → 초안 검토·CSV 다운로드.
2. **일일 재고 기록**: 실제 입고·폐기·마감 잔량 입력, FIFO 기준 입고 묶음별 잔량·사용기한 추정. 입력 없이 날짜를 건너뛴 재고를 만들지 않습니다.
3. **과거 발주 이력**: 제공된 합성 발주·입고 기록 조회.

기본 기준일은 2026-10-01입니다. 기록이 없다면 `초기 재고 9/30` → `발주 신청`으로 제공 재고를 바탕으로 시연하거나 일일 재고부터 입력하세요.

## 현재 연결 범위와 제한

- 프로모션 수정본의 비행사 기준 메뉴 수요를 Python에서 미리 계산하고, 화면에서 명시적 수요 반응 × BOM을 계산합니다.
- 과거 매장 행사일 전체를 기본 수요에서 제외합니다. 할인율만으로 수요 증가율을 만들지 않습니다.
- 할인 행사: 정률/정액 조건, 대상 메뉴·기간, 수동 수요 변화(-100~200%) 또는 동일 매장·동일 메뉴의 과거 행사 참고와 전이 가정 확인.
- 일반 특이사항: 수동 수요 변화 시나리오입니다. 메모를 LLM이 자동 해석하는 AI 에이전트는 아직 연결하지 않았습니다.
- 수요 변화가 반영되면 재고 전망·기한 경과 미소진 위험·기본 발주량을 다시 계산합니다. 그 후 선택한 발주량 배율을 적용합니다.
- `엔진 추천`은 현재 브라우저 발주 계산기의 기본값입니다. 팀의 전체 발주안 평가/정책 엔진과 확률·손실 비교는 아직 연결하지 않았습니다.
- 판매 관측은 2026-09-30까지, 미래 예측은 2026-10-14 기준일까지의 다음 7일입니다. 이후에는 최신 예측을 생성해야 합니다. 재고 입력만으로 모델이 재학습되지는 않습니다.
- 일일 기록과 행사 조건은 **브라우저 localStorage**에 저장됩니다. 여러 팀원·기기의 입력을 공유하는 DB/API는 없습니다. 행사 조건은 매장·기준일별이며 다음 기준일로 자동 승계되지 않습니다.
- CSV는 추천 초안이며 실제 공급사에 주문을 전송하지 않습니다. 실제 기록과 미래 시나리오는 구분합니다.
- 금액·매장·원천 기록은 제공된 합성 데이터 기반입니다. 포함된 JSON도 가공된 시연 데이터이므로 실제 운영 데이터로 교체할 때는 공개 범위를 검토하세요.

## 파일 구조

```text
web-dashboard/
  dist/                    # 그대로 배포할 웹 파일
    index.html, styles.css, app.js
    model-engine.js        # 공급사 일정·재고 시뮬레이션·발주 수량
    promotion-engine.js    # 조건 검증·메뉴별 배율·BOM 환산
    promotion-ui.js        # 특이사항 입력·미리보기·적용·브라우저 저장
    daily-*.js, lot-tracking.js, purchase-history.js
    data.json              # 가공 재고·마스터·조회 데이터
    purchase-history.json  # 가공된 과거 발주 이력
    team-forecasts.json    # 수정 모델의 기본 식자재 수요
    promotion-inputs.json  # 기본 메뉴 수요·BOM·과거 참고 배율
  scripts/                 # 데이터 재생성과 Python 출력 대조 테스트
  requirements-model.txt   # 재생성 작업에만 필요
  MODEL_INTEGRATION.md     # 모델 연결·입력 계약·재생성 안내
```

## 검증

Node.js가 설치된 환경에서 실행하세요. 추가 npm 패키지는 없습니다.

```sh
node web-dashboard/scripts/test-promotions.cjs
node web-dashboard/scripts/test-team-forecasts.cjs
```

검증 대상은 기본 수요 8,316개, Python 프로모션 출력 462개, 중복 행사 차단, 할인율·수요 반응 분리, 과거 참고 확인, 재고 불변성입니다. 모델 갱신 방법은 [MODEL_INTEGRATION.md](MODEL_INTEGRATION.md)를 참고하세요.
