# 설정과 이번 발주 요청

기준 브랜치: `engine-integration`, 기준 커밋: `3a5435c`.
기존 팀 발주/평가 엔진(`engine-core.js`)과 과거 오차 시나리오를 그대로 사용합니다.

## 실행

저장소 루트에서 Python 3.10 이상으로 실행합니다. 추가 패키지 설치는 없습니다.

```bash
python3 web-dashboard/serve.py
```

http://localhost:8000 에서 실행합니다. 정적 서버만 사용하면 숫자 설정과 계산은 가능하지만 자연어 해석 API는 제공되지 않습니다.

## 화면

- 첫 화면: 추천 금액 → 설정/주문 버튼 → 이번 요청 → 추천 품목.
- 주문 버튼은 검토 창을 열고, 확인 후 CSV로 저장합니다. 공급사 주문 전송은 기존과 같이 하지 않습니다.
- 다른 발주안은 작은 접이식 비교 영역에 있습니다.
- 설정: 기본 성향 / 발주 기준 / 한도·제외 품목 / 화면·저장.
- 기본 시작일은 기록이 있는 2026-09-30입니다. 화면 설정에서 변경할 수 있습니다.
- 이번 요청은 현재 세션에만 유지됩니다. 재로드 시 해제됩니다. 매장이나 날짜를 바꿔도 입력된 요청은 화면에 남아 적용됩니다.

## 자연어

기본은 원래 정책 패키지의 규칙 해석기를 사용합니다. 예:

- `안전하게, 30만원 이하`
- `이번에는 20만원 미만, 10% 여유, 우유 제외`
- `품절 가중치 3, 폐기 가중치 1`
- `서비스 수준 97%, 꼬리위험 비중 40%, CVaR 90%`

기본 성향 문장은 ‘문장으로 기준 채우기’로 해석한 뒤 저장합니다. 숫자는 직접 바꿀 수 있습니다.
이번 요청은 ‘요청 반영’을 눌러 적용합니다. 미해석/충돌/범위 오류가 있으면 주문을 진행하지 않습니다.
빈 요청을 반영하거나 ‘이번 요청 해제’를 누르면 저장한 기본 설정으로 돌아갑니다.
이번 요청의 명시 항목 > 저장한 숫자 설정 > 시스템 기본값 순입니다.
성향을 명시하면 프리셋의 6개 값이 먼저 적용되고, 개별 숫자가 뒤에 적용됩니다.
제외 품목은 기본 설정과 이번 요청의 합집합입니다. 설정 창에서 기본 제외를 해제할 수 있습니다.

자유 문장 해석은 사용자가 선택한 호환 API 제공사를 서버 환경변수로 설정한 뒤 사용합니다.
키는 브라우저나 Git에 저장하지 않습니다. 공급사별 무료 제공량과 비용은 직접 설정한 계정에 따릅니다.

```bash
export POLICY_API_URL='https://YOUR_PROVIDER/CHAT_COMPLETIONS_PATH'
export POLICY_API_MODEL='YOUR_MODEL'
read -s POLICY_API_KEY
export POLICY_API_KEY
python3 web-dashboard/serve.py
```

설정 → 기본 성향 → ‘자유 문장 해석 사용’을 켭니다. 기본 성향과 이번 요청 모두 같은 해석 모드를 사용합니다.
외부 API에는 입력 문장과 매장·식자재 이름/ID가 전송됩니다. 재고·판매 원본은 전송하지 않습니다.
API가 실패하면 요청 적용을 중단합니다. API 실호출은 제공사 키가 없어 검증하지 않았습니다.

## 계산

1. 기존 행사 엔진으로 메뉴 수요/BOM을 계산하고, 정책의 수요 배율을 적용합니다.
2. 기존 미입고 발주의 날짜에만 지연 가정을 적용합니다.
3. 기존 발주 엔진의 안전재고에 `추가 여유율 × 커버 기간 총수요`를 더해 수량을 만듭니다.
4. 사용자 서비스 수준과 90/95/99% 수준의 후보, 공급사 최소금액 연기/증량 후보 및 무발주 후보를 생성합니다.
5. 모든 후보를 **같은 사용자 가중치·CVaR**로 비교합니다. 서로 다른 점수 기준을 섞어 비교하지 않습니다.
6. 예산(미만/이하), 제외 품목, 공급사별·발주일별 최소금액, 품목 MOQ/정수, 품절/폐기 상한을 검사합니다.
7. 통과한 후보 중 점수가 낮은 안을 추천하고 동점이면 발주금액이 낮은 안을 선택합니다.
8. 수동 수정도 다운로드 전에 같은 엔진으로 다시 평가하고 제약을 검사합니다.

‘최적’은 생성된 후보 내 선택입니다. 모든 정수 수량의 전역 최적화가 아닙니다.
품절 확률은 기존 과거 오차 시나리오 빈도이며 현실 확률을 보장하지 않습니다.
품절 손실은 이익이 아닌 매출입니다. 발주지출은 손실 점수에 다시 더하지 않습니다.
기존 엔진처럼 품절은 보충 전까지, 폐기는 7일까지 계산합니다. 미래 신규 배송 지연은 모델링하지 않습니다.
발주는 현재 선택한 매장 단위입니다. 여러 매장 합산 예산 요청은 실행하지 않습니다.
긴급발주 허용은 기존 정책 스키마에는 있으나 긴급 후보는 현재 생성하지 않습니다.
재고·행사·기본 설정은 브라우저 localStorage에 저장되며 기기 간 공유되지 않습니다.
